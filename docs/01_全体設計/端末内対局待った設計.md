# 端末内対局「待った」設計

## 対象と境界

「待った」は `LocalMatchController` が管理する「AIと対局」「ふたりで対局」だけを対象とする。`OnlineMatchController`、WebRTC、オンライン棋譜、レーティングには依存させない。

責務は次のように分ける。

- `:feature:match`: 現在局面、実着手履歴、待った可否、AI対局の `undoUsed`、AI requestの有効性
- `:analysis:edax`: AIレベル・思考時間と、evaluation data / opening book の正規メタデータをまとめた対局開始時条件
- `:app`: AI探索の実行・cancel、条件表示、終局棋譜保存の取消連携
- `:feature:records`: 棋譜モデルと保存インターフェース

`undoUsed` をEdax設定へ保存せず、evaluation/book情報を対局履歴へ複製しない。

## 実着手チェックポイント

合法な実着手を適用する直前に、次を1チェックポイントとしてメモリ内へ保持する。

- `GameState` 全体（盤面、手番、`consecutivePasses`、`ply`）
- その時点までの棋譜列
- 着手者

強制パスは棋譜列へ `null` として残すが、ユーザーの意思決定ではないため独立チェックポイントにはしない。盤面だけや固定ply数を戻す方式を採らないことで、強制パス・終局を跨いでも手番と連続パス数を正確に復元する。

ふたり対戦では最後のチェックポイントを1件戻す。AI対局では、着手者が人間である最後のチェックポイントへ戻し、その後のAI応手を含むチェックポイントをまとめて破棄する。したがって意味は固定2plyではなく「人間が直前に意思決定した局面へ戻る」である。

戻せるチェックポイントがない操作は不成立であり、状態を変更しない。AI対局で正常に復元できた場合だけ `undoUsed = true` とし、その一局では単調に維持する。新しい対局へのreset時だけ `false` に戻す。

## AI探索の競合防止

AI探索開始時に、対局コントローラーが次を含む `LocalAiTurnRequest` を発行する。

- 単調増加request ID
- 局面世代
- 探索対象の不変 `GameState`

待った、reset、画面終了、着手確定などでrequestを無効化する。AI結果を適用する直前に、active requestの同一性、局面世代、探索対象局面と現在局面の一致をすべて再検証する。

AI思考中の待ったでは、まず `AiMoveEngine.cancel()` でEdax側へ停止を要求し、続けて対局側requestを失効させてからチェックポイントを復元する。ネイティブcancelが間に合わず古い結果が返っても、完了時検証で破棄される。古いrequestのfinally処理も、新しいrequestの思考中状態を変更できない。

## AI対局条件のスナップショット

`EdaxDataManager.aiMatchConfiguration()` が、1回の `commonDataStatus()` から次をまとめて返す。

- `AiMoveSettings`（レベル、1着手の思考時間、利用するデータソース）
- evaluation data の既存 `ImportedAnalysisFile` メタデータ
- opening book の既存 `ImportedAnalysisFile` メタデータ

画面は対局開始時にこれをスナップショットし、その一局の全AI着手と表示へ同じ値を使う。新しい対局を開始した時だけ再取得する。このため、表示は一局で実際に使用した条件を表し、画面自身がファイルを読んだりSHA-256を再計算したりしない。

表示はレベル、思考時間、待ったあり／なしに加え、各データの表示名、サイズ、full SHA identityの先頭8文字とする。未設定は明示し、長い表示名だけをellipsisで省略してサイズと短縮SHAを残す。

## 終局棋譜と待った

既存仕様では終局時にプロセス所有の保存処理を即座に開始する。終局後の待ったが成立した場合は、その `completedRecord` を無効化し、`LocalGameRecordPersistenceCoordinator.discard()` で保存先から削除する。

discardは同じlocal IDの保存jobをcancelしたうえで完了を待ち、その後にdeleteする。保存処理がcancelを無視して遅れて書き込んでもdeleteが最後になる。操作世代を検証し、古いsave完了がdiscard状態を上書きしない。削除失敗はプロセス所有状態へ残して再試行可能にする。

再び終局した場合は、復元後に確定した棋譜列だけから新しい `LocalGameRecord` を生成する。

## UI

- 初期局面など不成立時は「待った」をdisabledにする。
- AI思考中でも人間の直前着手があれば「待った」を有効にする。
- AI対局だけ対局条件を3行で常時表示する。
- ふたり対戦には待った使用履歴を表示しない。
- 終局後も盤面、石数、結果、AI条件、待った有無を同じスクロール画面で確認できる。

## テスト方針

純粋な対局コントローラーテストで、1手／連続待った、分岐打ち直し、強制パス、終局、AIの人間意思決定単位、`undoUsed` を確認する。アプリ層では非協力的な遅延AI結果の拒否、保存中recordの順序付きdiscard、条件メタデータと長いファイル名表示契約、オンライン画面との分離を確認する。
