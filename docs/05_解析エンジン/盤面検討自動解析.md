# 盤面から検討の自動解析設計

## 対象と非対象

この文書は、`PositionReviewScreen`（「盤面から検討」）で現在局面の全合法手を自動解析し、盤面上へ評価値を表示する設計を定義します。

対象は盤面検討セッションだけです。オンライン棋譜・オフライン棋譜の`ReviewScreenV2`を含む棋譜レビュー画面は、従来どおり明示操作で解析します。盤面検討の着手、前後移動、強制パス、保存、再オープンの責務は変更しません。

## 責務の分離

| 要素 | 責務 |
| --- | --- |
| `PositionReviewSession` | 初期局面、着手履歴、cursor、前／次／reset、着手後の強制パス解決を管理する |
| `PositionReviewScreen` | 現在局面の変化をCompose stateへ反映し、解析開始、状態表示、盤面表示、cancelを行う |
| `PositionReviewAnalysisCoordinator` | request世代、現在性の判定、解析設定境界、64局面LRUを管理する |
| `PositionReviewAnalysisRequest` | request作成時の不変な`GameState`と`AnalysisSettings`を保持し、その組み合わせを解析する |
| `AnalysisRequestGuard` | generationと`stateHash()`により、同じ局面へ戻った場合も古いrequestを拒否する |
| `ProductionAnalysisEngine` | 単一background workerでEdaxを実行し、request ID単位のnative cancelとcoroutine cancellationを処理する |

## 自動解析のトリガー

`PositionReviewScreen`の`LaunchedEffect`は、次の値をキーにします。

- 現在局面の`stateHash()`
- エラー時の手動再試行世代
- Edax利用可否または評価データ未設定の状態
- 解析レベル
- 1候補あたり解析時間
- evaluation dataのSHA-256
- opening bookのSHA-256

画面を開いた直後は初期局面のキーで起動します。合法手の着手、「前」、「次」、「初期局面へ戻る」は`PositionReviewSession`を更新してrevisionを進めるため、新しい現在局面のキーで自動解析が起動します。

失敗状態そのものは`LaunchedEffect`のキーに含めません。このため、解析失敗後に同じ局面を自動で無限再試行しません。失敗時だけ表示する「再試行」が再試行世代を明示的に進めます。

## 解析開始から表示まで

1. 局面操作のイベントハンドラは、`AnalysisRequestGuard`を即時invalidateし、`engine.cancel()`を呼び、盤面用の解析結果を`null`へ戻します。
2. 新しい`LaunchedEffect`も開始時に`engine.cancel()`を呼び、前requestの終了を促します。
3. coordinatorが現在局面と設定からrequestを開始します。
4. 合法手がなければ、解析せず評価値なしの状態を確定します。
5. セッションLRUに同じキーがあれば、`解析中…`へ遷移せず、その結果を盤面へ設定します。
6. cache missの場合だけ、requestに保存した局面と設定で`AnalysisEngine.analyze()`を実行します。
7. 完了時にcoordinatorがrequest generation、現在局面、現在設定を再検証します。すべて一致し、かつ`AnalysisResult.available`が`true`の場合だけ結果をLRUへ保存して盤面へ表示します。
8. 不一致、cancel、例外、`available == false`は表示にもセッションLRUにも反映しません。

## race conditionとcancelの防御

cancelは完了を保証する同期処理とはみなしません。次の防御を重ねます。

1. **操作時の即時消去**: 局面変更のイベント内で旧評価値を消すため、再composeまで別局面の値を残しません。
2. **Compose coroutineのcancel**: `LaunchedEffect`のキー変更により旧effectをcancelします。
3. **Edax requestのcancel**: `engine.cancel()`が現在のnative request IDを`EdaxExecution`へ渡します。
4. **request generation**: 新しい`begin()`または`invalidate()`がgenerationを進めます。A解析中にBへ移り、再びAへ戻っても、最初のA requestは最新generationではないため拒否されます。
5. **局面・設定の再照合**: 完了時にrequestのcache keyと現在の盤面、手番、解析設定、データSHAを比較します。
6. **不変な解析入力**: requestは作成時の`GameState`と`AnalysisSettings`を保持します。セッションcursorが先に動いても、Edaxへ渡す局面はすり替わりません。
7. **engine側のcancellation確認**: `ProductionAnalysisEngine`はnative処理後にcoroutineの`ensureActive()`を確認してから、engine内部cacheへ保存します。cancel済みcoroutineはその保存地点へ到達しません。

旧requestの`finally`も最新requestかを確認してから`running`を変更します。このため、遅れて終了した旧requestが新requestの「解析中」表示を解除しません。

## 64局面LRUキャッシュ

盤面検討専用cacheは`PositionReviewAnalysisCoordinator`のインスタンスが所有します。`LinkedHashMap`のaccess-orderを使い、最大64件を保持します。

- cache hitの`get`は、そのentryを最終アクセス位置へ移動します。
- 65件目を保存すると、アクセス時刻が最も古いentryを1件削除します。
- FIFOではありません。古いentryでも再アクセスされていれば保持されます。
- 画面から離れると`clear()`し、永続化しません。
- 正常完了し、完了時点でも最新requestである結果だけを保存します。

cache keyは次を含みます。

- `Board.toCompactString()`による盤面全64マス
- 手番
- 解析レベル
- 1候補あたり解析時間
- evaluation dataのidentity SHA-256（未設定は`null`）
- opening bookのidentity SHA-256（未設定は`null`）

requestの現在性確認には、上記cache keyに加えて`GameState.stateHash()`を使用します。`stateHash()`は盤面hash、手番、連続pass数、plyを含みます。

`ProductionAnalysisEngine`には従来から実装詳細として別の小容量cacheがあります。盤面検討の64件LRUがhitした場合はengineを呼びません。セッションLRUがmissしてengine内部cacheがhitした場合もnative Edaxは実行されませんが、返却結果は通常のrequest完了と同様にcoordinatorの現在性検証を通過しなければ表示・セッション保存されません。

## cacheのclear条件

coordinatorは、前回と次の解析構成が異なる場合に64件LRUを全消去します。比較対象は解析レベル、候補時間、evaluation SHA、book SHAです。key自体にも同じ値を含め、異なる構成の結果を再利用しない二重の境界にします。

画面破棄時にもrequestをinvalidateし、LRUをclearしてEdaxをcancelします。設定画面へ移動した場合も画面破棄を経るため、戻った後に変更前の結果は残りません。

## エラーと解析対象なし

- Edax nativeが利用できない場合、またはevaluation dataが未設定の場合は解析を開始せず、既存の設定導線を表示します。
- `AnalysisResult.available == false`、例外、cancel、stale resultはcacheへ保存しません。
- 通常エラーでは自動再試行せず、同じ局面に対する「再試行」を利用者が明示できます。
- 合法手がない局面ではengineを呼ばず、盤面評価値を空にします。前局面の評価値は操作時とeffect開始時の両方で消去済みです。

## テスト境界

`:feature:review:test`では、初期局面からの解析、着手・前・次・reset、A→B→Aのcache hit、engine非再実行、64/65件LRU、recent access、解析設定変更、cancel／失敗時の非保存、Aの遅延完了、連続前後操作、合法手なし、request入力局面の固定を検証します。

`:app:testDebugUnitTest`のUI構造契約では、自動解析coordinatorの利用、局面操作時のinvalidate／cancel／結果消去、「全合法手を解析」ボタンが存在しないことを確認します。
