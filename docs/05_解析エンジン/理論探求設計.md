# 理論探求 設計

## 目的と非目的

「理論探求」は、同じ盤面上で次の3つを見比べながら、利用者が指標の意味を自分で調べるための一時研究セッションです。

- Edaxによる全合法手の探索評価
- 盤面と候補着手だけから決定論的に計算する理論指標
- 実際の石配置と変化

理論指標を正解や総合評価として提示しません。Edax評価から理論指標を派生させず、複数指標を合成した順位も作りません。保存棋譜、棋譜名、メモ、Research投稿はこの機能の責務ではありません。

## 境界

| 要素 | 責務 |
| --- | --- |
| `:core:game` | 盤面、合法手、着手、反転、強制パス、終局 |
| `:analysis:api` | Edax実装に依存しない解析request／result契約 |
| `:feature:theory` | 変化木、4指標の定義と計算、session snapshot、解析世代、cache契約 |
| `TheoryExplorationScreens.kt` | Compose state、盤面2段表示、分岐選択、指標切替、解析の開始とcancel |
| `TheorySessionFileStore.kt` | 一時session JSONのatomicな端末保存とprocess寿命のwrite調停 |
| `TheoryAnalysisFileCache.kt` | build単位、100MB、disk LRUのAndroid実装 |
| `:analysis:edax` | JNI、native request cancel、Edax固有変換と小容量memory cache |

`:feature:theory`は`:feature:review`にも`:analysis:edax`にも依存しません。`ReviewScreenV2`、`PositionReviewScreen`、保存棋譜のモデルへ理論探求固有ロジックを追加しません。共通利用するUIは、盤面枠だけを描く純粋な`CoordinateBoard`です。合法手セルの2段表示は専用Composableに置き、棋譜レビューの1段表示を変更しません。

## 変化木

`TheoryExplorationSession`は初期配置をroot nodeとする木を所有します。各edgeが利用者の1着手、各nodeが着手後の強制パスを解決済みの`GameState`です。

- 新しい合法手は現在nodeのchildとして追加します。
- 同じchild着手がすでにあれば新nodeを重複作成せず、そのchildを選択します。
- 親へ戻って別の手を打っても既存childとその子孫を削除しません。
- childが1件なら「次」で直接進みます。2件以上なら、座標を並べる最小限の選択ダイアログを表示します。
- 着手後は`TurnResolver.resolveForcedPasses()`を必ず通します。相手だけ合法手なしなら同じ側が再び手番となり、両者合法手なしなら2回のpassを経て終局nodeになります。

node IDはセッション内だけで安定すればよく、盤面cache keyには使いません。このため別経路から同じ盤面・手番へ到達した場合も解析結果を再利用できます。

## 一時セッション復元

`TheorySessionSnapshot` schema version 1は次を保存します。

- 全nodeのID、parent ID、親からの着手
- 現在node IDと次に採番するID
- 選択中の指標ID
- 現在盤面、手番、連続pass数、ply

復元時は初期配置から全edgeを再生します。ID重複、cycle、孤立node、非合法手、同じ親の重複着手、現在盤面との不一致、未対応schemaのいずれかがあればsnapshot全体を採用しません。JSON破損または意味検証失敗はクラッシュさせず、破損ファイルを隔離して初期sessionから開始します。未知の指標IDだけは、指標削除後にも木を救済できるよう既定指標へ戻します。

保存先はアプリprivateの単一JSONであり、保存棋譜一覧には接続しません。画面scopeではなくprocess scopeの`TheorySessionPersistenceCoordinator`が書込みを所有します。高速操作中は途中snapshotをまとめ、常に最新snapshotまでatomic writeします。画面を離れた直後も開始済みwriteは画面破棄でcancelされません。失敗時は最新snapshotを保持し、画面から明示的に再試行できます。

## 指標レジストリ

`TheoryMetricRegistry`の各`TheoryMetricDefinition`は、安定ID、表示名、計算関数、良い方向、短い説明、詳細説明、値域説明、注意文、formatterを所有します。画面とViewModel相当の処理は4つのIDに対する`if`を持たず、registryを列挙します。指標の追加時は原則としてdefinition 1件を追加するだけで、一括計算、切替、説明表示へ反映されます。

`TheoryMetricEvaluator.evaluateAll()`は局面変更時に合法手ごとの着手後盤面と反転石を一度作り、そのcontextから全指標をまとめて計算します。選択指標の切替では再計算せず、保持済みmapから表示値だけを切り替えます。指標の入力は`GameState`、候補`Position`、着手直後の`Board`、反転石だけです。`AnalysisResult`、Edax評価、PV、深さ、selectivity、book値を参照できません。

### 初版4指標の固定定義

| ID | 表示名 | 定義 | 一般的な方向 |
| --- | --- | --- | --- |
| `openness` | 開放度 | 候補手で反転した各石について、着手直後の8近傍にある空きマス数を合計する。同じ空きマスが複数の反転石に接すれば重複して数える | 小さい方 |
| `opponent_mobility` | 相手モビリティ | 候補手の着手直後、pass解決前に相手が持つ合法手数 | 小さい方 |
| `frontier_discs` | フロンティア石数 | 着手直後、今打った側の石のうち8近傍に1つ以上の空きがある石の枚数。1枚は1回だけ数える | 小さい方 |
| `potential_mobility` | 潜在モビリティ | 着手直後、今打った側から見て相手石に8近傍で接する空きマスの集合サイズ。1空きマスは1回だけ数える | 大きい方 |

すべて「今から打つ側が候補手を打った場合」の視点です。相手モビリティ0は相手passを意味します。潜在モビリティは複数ある用語定義のうち、本表の「相手石に接する一意な空きマス数」を本アプリ初版の定義として固定します。確実な最小値0だけを説明し、未検証の理論最大値はUIへ固定しません。

## 盤面表示と操作

合法手セルの意味は常に次の順です。

```text
上段: Edax評価
下段: 選択中の理論指標の生値
```

解析待ちは上段を`…`、利用不能または失敗は`—`とし、下段の指標はEdax待ちと独立して即座に表示します。両段は1行、省略表示を許可してセル幅を越えないようにします。指標切替は左右buttonと中央の名前／方向で行い、切替にdialogを使いません。現在指標の直感的説明と固定定義は操作領域の下に表示し、画面全体を縦scroll可能にします。

画面には棋譜名、メモ、保存棋譜、変化破棄、棋譜情報を置きません。

## 自動解析

初期session、復元node、新規着手、親へ戻る、childへ進む、別child選択のすべてで現在局面の全合法手解析を自動開始します。指標切替は解析triggerではありません。

解析effectのkeyは次です。

- 盤面64マスと手番からなるposition identity
- retry世代
- native／evaluation dataの利用状態
- level
- 1候補あたり時間
- evaluation data SHA-256
- opening book SHA-256

同一keyのcache hitでは`AnalysisEngine`を呼ばず、「解析中…」へ遷移せず結果を表示します。合法手なしではcacheもengineも使いません。通常失敗は自動再試行せず、利用者が「再試行」を押したときだけretry世代を進めます。

## race conditionとcancel

cancelの完了だけを安全性の根拠にしません。

1. 局面操作イベントでrequest generationをinvalidateします。
2. 同じイベントで`engine.cancel()`を呼び、旧盤面の`AnalysisResult`を即座に`null`へ戻します。
3. Composeの解析effectはposition key変更でもcancelされます。
4. requestは開始時の不変な`GameState`、`AnalysisSettings`、cache key、generationを保持します。
5. Edax完了時に、generation、現在盤面、手番、level、候補時間、eval SHA、book SHAを再照合します。
6. 正常で全合法手が揃い、完了時点でcurrentな結果だけをdisk cacheへ書きます。
7. disk writeには所有tokenを付け、write後にもcurrentか再確認します。write中に無効化された場合は、そのtokenが所有するentryだけを条件付き削除します。同じkeyへ新requestが保存済みなら、その新entryは削除しません。
8. write後もcurrentな場合だけ盤面へ表示します。
9. 旧requestの例外／`finally`もcurrentな場合だけerror／running stateを変更します。

A解析中→Bへ移動→Aへ戻る競合でも、最初のAはgenerationが違うため拒否します。cancel済み、stale、不完全、`available == false`、例外結果は理論探求cacheへ保存しません。engine側でもnative完了後の`ensureActive()`を通過した結果だけがengine内部memory cacheへ入ります。

## 100MB解析LRU

`JsonFileTheoryAnalysisCache`はアプリcache directory内に、完全な全合法手`AnalysisResult`をkeyごとのJSON fileとして保存します。容量上限は`100 * 1024 * 1024` bytesです。「局面数」ではなくentry fileの実byte数を合計します。

cache keyは次を含みます。

- `Board.toCompactString()`による64マス
- 手番
- level
- 1候補あたり時間
- evaluation data identity SHA-256
- opening book identity SHA-256

tree node、経路、ply、選択指標はkeyへ入れません。これらはEdax結果を変えないためです。key全体のSHA-256だけを安全なfile nameに使い、JSON内にも元keyを保存して衝突／取り違えを検査します。

hit時はentryの最終更新時刻を更新します。put後に合計が100MBを越えた場合、最終利用時刻が古いfileから削除します。FIFOではありません。破損entryはその1件だけを削除し、他entryを維持します。評価データまたはbookを設定画面で変更した場合はcache全体をclearし、level／時間変更はkey不一致によって旧値を使いません。

cache directoryのmarkerにはcache schemaと`BuildConfig.VERSION_CODE`を保存します。どちらかが変わった最初のaccessで全entryを削除します。cacheは高速化データであり、形式migrationやユーザー資産としての保証は行いません。一時session JSONは別保存先なので、cache破棄で変化木は失われません。

## テスト境界

`:feature:theory:test`は次を検証します。

- 通常、角、辺、複数方向反転と4指標の固定値
- 開放度の重複加算、フロンティア石の非重複、潜在モビリティ空きマスの非重複
- 相手モビリティ0、強制pass、終局
- 分岐生成、元分岐保持、分岐選択、同じchildの非重複、snapshot復元と破損拒否
- 初期／着手後解析、A→B→A cache hit、設定key、遅延結果、cancel invalidate、高速移動、合法手なし
- 一時session writeの最新snapshotへの集約とretry

`:app:testDebugUnitTest`は100MB disk LRU、recent access、容量超過、build番号変更、破損entry、一時session file復元、日英resource、ナビゲーション、専用画面の自動解析／2段表示／レビュー分離を検証します。`scripts/check-boundaries.ps1`は`:feature:theory`から`:feature:review`、`:analysis:edax`、WebRTC、Supabase SDKへの依存を拒否します。
